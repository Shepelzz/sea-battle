## 2. Модель данных

Вся партия — один JSON-объект, целиком сохраняемый в БД (`games.state`). Схема — `createGame` в `server/game.js`.

```js
game = {
  id, status: 'lobby' | 'active' | 'finished',
  config: { maxPlayers, turnTimer, seed, mode, fog, multiMove, realtime,
            listed, hotseat, botGame },
  map: { w, h, bases[], lootIslands[], fishZones[] },
  players: [{ id, nick, color, gold, portHp, alive, placement, stats,
              isBot, botLevel, ready, earned }],
  ships:   [{ id, owner, type, x, y, hp, heading, repairCharges, dest, cd, ... }],
  wind:    { ang, str, targetAng, targetStr },
  turn:    { idx, number, round, deadline, moves, actedShips, broadsideSides, nudged },
  rt:      { startedAt, nextIncome, nextFish, nextCast, nextSave, paused, ... },
  log: [], events: [], eventSeq, winner, hostPid, hotseatOwner, createdAt, updatedAt
}
```

Ключевые соглашения:

- **`owner`**: индекс игрока, либо `-1` для пирата. Везде, где встречается `owner === -1`, речь о NPC.
- **`turn.idx`** — чей ход; **`turn.number`** — сквозной счётчик ходов; **`turn.round`** — полный круг (для мирного периода).
- **`ship.cd`** — реалтайм-кулдауны: `{ p, s, m, r }` (левый борт / правый / мортира / ремонт), значения — `Date.now()`-метки готовности.
- **`player.earned`** — временный аккумулятор доходов за ход, сбрасывается в журнал через `flushEarnings`.
- Карта — круги в логике; `shape` у островов нужен только для отрисовки.

## 3. Жизненный цикл партии

```
lobby ──startGame──> active ──последний живой порт──> finished
  │                    │
  │                    └── дуэль: phase 'buy' → 'battle'
  └── TTL: 6 ч неполное / 24 ч укомплектованное
```

- **Создание**: `POST /api/games` (`server/index.js`). Три ветки — `hotseat` (старт сразу, все ники вводятся на главной), `bot` (человек + 1–3 бота, старт сразу), онлайн (лобби, `config.listed = true`).
- **Онлайн требует аккаунт**, если Google-вход настроен. Одно открытое лобби на аккаунт — второе не плодим, возвращаем в существующее.
- **Старт**: `startGame` генерирует карту, раздаёт `START_FLEET`, спавнит стартовых пиратов.
- **Победа**: `eliminatePlayer` → когда живых остался один, `status = 'finished'`, `winner` = его индекс.
- **Аварийное завершение**: `forceFinish` выбивает слабейших по `hp + dmg + portHp`, пока не останется один. Используется, когда доигровка за ботов упёрлась в лимит, и в кнопке «завершить» у хоста.
- **Уборка**: раз в 10 минут сборщик в `server/index.js` сносит просроченные лобби (`lobbyExpired`) и заброшенные партии (`gameStale`, `GAME_STALE_MS` = 7 дней) — и из памяти, и из БД.
- **Переживает рестарт**: все активные игры грузятся из БД в `bootstrap()`.

TTL лобби: `LOBBY_TTL_PARTIAL_MS` (6 ч, заняты не все места) и `LOBBY_TTL_FULL_MS` (24 ч, все места заняты, но не начато).

## 4. Ход и бюджет действий

Пошаговая игра. Один ход = бюджет **манёвров**:

- `MOVES_PER_TURN = 3` — бюджет в режиме «ход тремя судами» (`config.multiMove`, по умолчанию **включён**).
- Классика (`multiMove: false`) — бюджет 1: любое действие завершает ход.
- Считает `movesBudget(cfg)` в `server/config.js`.

Правила расхода (конец `applyAction`):

| Что | Стоимость | Помечает корабль «сходившим» |
|---|---|---|
| движение, мортира, ремонт, пополнение, постройка аванпоста | 1 манёвр | да |
| покупка в верфи, сбор клада | 1 манёвр | сбор — помечает собравшие корабли |
| бортовой залп | 1 манёвр **за каждый борт** | только после **обоих** бортов |
| ⛵ конвой | `convoyCost(n)` = **1** на весь строй | все суда строя |
| апгрейд аванпоста | 1 манёвр | нет (корабль не нужен) |

- Одним кораблём за ход — не больше одного действия (`turn.actedShips`). Исключение — залп: после одного борта кораблю доступен только второй борт.
- Ход закрывается сам, когда бюджет исчерпан, **или** когда у игрока физически не осталось действий (`playerHasAction`: нет нехоженого корабля и не хватает на самый дешёвый в верфи). Это про концовку партии, где 3 манёвра не выбрать.
- `SHIP_ACTIONS = ['move','attack','broadside','repair','recharge','outpost']` — действия, привязанные к кораблю.

**Таймер хода**: `config.turnTimer` ∈ {0, 60, 120, 300} с. `timeoutTurn` пропускает ход по дедлайну. В реалтайме дедлайн всегда `null`.

**📯 Поторопить** (`nudge`): ставит жёсткие `NUDGE_MS` = 10 минут и шлёт письмо, если у адресата есть почта. Раз за ход, не себе, не в реалтайме, не в хотсите; не сработает, если до конца таймера и так меньше 10 минут. Письмо уходит **на языке адресата** (`players.lang`).

## 5. Действия (`applyAction`)

Все ходы идут через одну функцию в `server/game.js`. Она же — единственная точка валидации: бот, человек и реалтайм используют её одинаково.

| `action.type` | Что делает | Главные отказы |
|---|---|---|
| `buy` | Покупает список кораблей, спавнит веером у своей базы | `err.noGold`, `err.noRoomNearPort` |
| `collect` | Забирает клад со всех досягаемых незалутанных островов (`LOOT_REACH = 55`); лутают только ещё **не ходившие** корабли, и сбор помечает их сходившими | `err.nothingToCollect` |
| `move` | Перемещает корабль в точку в пределах `move × ветер` | `err.tooFar`, `err.windTooFar`, `err.blocked.*` |
| `convoy` | Ведёт строй до `CONVOY_MAX = 3` судов одним жестом | `err.convoyContact`, `err.convoyRank`, `err.convoySlow` |
| `attack` | 🎯 Мортира по кораблю / порту / аванпосту | `err.mortarOnlyHeavy`, `err.targetOutOfRange` |
| `broadside` | 💥 Бортовой залп по всем врагам с выбранного борта | `err.noTargetsOnSide`, `err.sideUsed*` |
| `repair` | 🛟 Чинит союзника в радиусе, тратит заряд | `err.noMaterials`, `err.noSelfRepair` |
| `recharge` | 🔧 Пополняет заряды ремонта у своей базы | `err.rechargeAtBase` |
| `outpost` | ⛺ Строит или прокачивает аванпост на залутанном острове | `err.lootFirst`, `err.enemyOutpost`, `err.outpostMaxed` |
| `buyPerk` | 🎖 Покупает перк за золото + 🪙 монеты (разово) | `err.perkOwned`, `err.noCoinsFor`, `err.perksOffHere` |
| `buyFleet` | Дуэль, фаза закупки: собрать флот на всё золото | `err.spendAllGold`, `err.badDuelShip` |
| `rtPause` | ⏸ Пауза реалтайма (ставит и снимает любой живой) | `err.pauseRtOnly` |
| `skip` / `endTurn` | Пропустить / завершить ход | — |

**Отказы — это ключи, а не фразы**: `{ ok: false, error: 'err.notYourTurn', params: {...} }`. Текст собирает клиент (`errText` в `public/js/i18n.js`). Причина — в разделе 20.

**Размещение корабля** (`shipPlacementBlocked`) запрещает: за краем карты (`MAP_EDGE_MARGIN = 12`), на базе/острове (`ISLAND_BLOCK_GAP = 14`), вплотную к другому кораблю (`SHIP_COLLISION_DIST = 26`). В реалтайме корабли друг другу не мешают (`terrainBlocked` — только суша и края), иначе плывущие вечно клинят.

## 6. Бой

### 💥 Бортовой залп — основная атака

Весь борт бьёт по **всем** врагам с этой стороны в радиусе. Урон по каждой цели:

```
dmg = SHIP_TYPES[type].dmg × angle × falloff
  angle   = 1.0 на перпендикуляре борта → BROADSIDE_SIDE_MIN на краю сектора
  falloff = 1.0 в упор                  → BROADSIDE_FALLOFF_MIN на краю радиуса
```

- `BROADSIDE_HALF_ARC = 0.8` рад (~46° в каждую сторону) — нос и корма не задеваются.
- `BROADSIDE_SIDE_MIN = 0.6`, `BROADSIDE_FALLOFF_MIN = 0.6`.
- Эффективный урон по классам (база → минимум): шхуна 15→5, бриг 28→10, фрегат 42→15, линкор 65→23.
- По вражескому **порту** залп символичен: `BROADSIDE_PORT_MULT = 0.12`. Осада — дело мортиры.
- Борт выбирается **прицелом**: куда целишься, тот борт и стреляет. Пошагово каждый борт — раз в ход (`turn.broadsideSides`); в реалтайме у каждого борта свой кулдаун.
- Пушек на борт (`BROADSIDE_CANNONS`) — только для визуала трассеров и таблицы флота; на урон не влияет.
- Баркасы **не исключены** из-под залпа: попадает всё, что оказалось в секторе.

⚠ **Баркас и ремонтник стрелять не умеют вообще**: пушек на борт у них нет, мортира — только у
фрегата и линкора. Поле `dmg = 5` у баркаса живёт лишь в оценках угрозы (ИИ, логика пиратов).

### 🎯 Мортира — прицельный одиночный выстрел

- Доступна только `MORTAR_SHIPS = ['fregat','linkor']` (+ чит-авианосец).
- По **судам** бьёт вполовину: `MORTAR_SHIP_MULT = 0.5`.
- По **портам и аванпостам** — полным уроном; у линкора ещё `portBonus = 1.5` (65 × 1.5 ≈ 98).
- Мортира — **единственное**, что разрушает чужой аванпост.

### 🏰 Порт

- `PORT_HP = 840`.
- Огрызается по атакующему кораблю: `PORT_RETURN_DMG = 25`, линкору — `PORT_RETURN_LINKOR_MULT = 1.2` (30). Обломки достаются защитнику.
- Сам по площади не стреляет: `PORT_DMG_TO_SHIPS = 0` (константа мертва, оборона — флотом).
- Разбит → игрок выбывает, флот тонет вместе с портом, победитель забирает **куш** (раздел 8).

### Потопление

`sinkShip`: корабль исчезает, летит событие взрыва, убийца получает лут (раздел 8). Пират даёт `bounty`. В дуэли за вражеское судно золото **не дают** — только за пиратов.

## 7. Флот

`SHIP_TYPES` в `server/config.js`. Расстояния в игровых единицах, **1 клетка = 40**.

| Тип | Иконка | Цена | HP | Урон | Дальность огня | Ход | Особое |
|---|---|---|---|---|---|---|---|
| `barkas` | ⛵ | 60 | 30 | 5 | 70 | 180 | 🐟 пассивная рыбалка +5/ход |
| `shkhuna` | 🛥 | 110 | 60 | 15 | 110 | 170 | стартовый корабль ×2 |
| `brig` | ⚓ | 220 | 110 | 28 | 140 | 135 | порог «боевого судна» |
| `repair` | 🛟 | 280 | 130 | 0 | 115 | 135 | чинит союзников, не атакует |
| `fregat` | 🚢 | 380 | 170 | 42 | 165 | 110 | стартовый; мортира + залп |
| `linkor` | 🛳 | 500 | 280 | 65 | 190 | 90 | 🏰 мортира по порту ×1.5 |
| `carrier` | 🛩 | 0 | 1400 | 65 | 320 | 280 | ⚙️ чит-корабль, залп из 5 снарядов |

- **Старшинство** (`shipRank`) = цена класса. Нужно конвою: флагман не может быть младше ведомых, иначе баркас с ходом 180 таскал бы линкоры.
- **«Боевое судно»** = бриг и выше, не ремонтник. По этому признаку журнал выбирает формулировку для конвоя.
- **Старт**: `START_FLEET = ['shkhuna','shkhuna','fregat']`, `START_GOLD = 350`.
- Чит-корабль скрыт из верфи, вики и `publicState`, пока `CHEATS_ENABLED` выключен.

### 🛟 Ремонтник

- За действие чинит **одного** союзника в радиусе на `REPAIR_HEAL_FRAC = 0.15` от **максимального HP цели** (не фикс — иначе мелкому это полное лечение, а линкору крохи).
- Запас: `REPAIR_CHARGES = 8`. Кончились — вернуться к своей базе (`REPAIR_DOCK_REACH = 60`) и сделать `recharge`.
- Себя не чинит.

### ⛵ Конвой (ход строем)

- До `CONVOY_MAX = 3` судов, набор из соседей флагмана в радиусе `move флагмана × CONVOY_PICK_MULT = 1`.
- Стоит **один** манёвр на весь строй — в этом и смысл фичи.
- Три ограничения держат его честным: идёт по самому медленному; не собирается в боевом контакте (`shipInContact` — рядом чужой в пределах своей или его дальности огня); флагман не младше ведомых.
- Стрелять строем нельзя — это чистая логистика.
- Только пошагово и только при `multiMove`.

## 8. Экономика

### Источники дохода

| Источник | Сколько | Когда |
|---|---|---|
| Порт | `PORT_INCOME = 6` + поддержка отстающего | начало своего хода |
| 🐟 Рыбалка | `FISH_INCOME = 5` за баркас в зоне | начало своего хода, пассивно |
| 🏝 Клад | 100–300 (`LOOT_VALUE_*`) | действием `collect` |
| ⛺ Аванпост | 3 / 8 / 12 по уровням | начало своего хода |
| 🏴‍☠️ Пират | 150–350, босс 400–800 (+🪙 1, босс 2) | при потоплении |
| Обломки | `WRECK_LOOT_FRAC = 0.5` от цены судна | при потоплении (в реалтайме — `RT.WRECK_LOOT_FRAC`) |
| Куш за базу | 100–1000 | при выбивании игрока |

### 🆘 Поддержка отстающего

Не ступенька «есть корабли / нет», а плавный спад по стоимости флота:

```js
poor = max(0, 1 − fleetValue / PORT_POOR_FLEET)
income = round(PORT_INCOME × (1 + (PORT_POOR_MULT − 1) × poor))
```

`PORT_POOR_MULT = 2.5`, `PORT_POOR_FLEET = 220` (цена брига).
Итог: пусто → 15/ход · баркас → 13 · шхуна → 11 · от брига и дороже → 6.

**Почему не плоский множитель:** при «×3, пока судов нет» покупка первого баркаса роняла доход с 18 до 6, а ловил он всего 5 — выгоднее было сидеть без флота. Плавный спад убирает эту ловушку.

В журнал попадает двумя статьями: `income.port` и `income.support`.

### 🐟 Рыбалка

- Пассивная: баркас, стоящий в зоне, приносит улов в начале хода владельца, действие не тратится.
- Лимит на зону: `FISH_ZONE_CAP = 4`, у крупных зон `FISH_ZONE_CAP_BIG = 5` (крупная — радиус ≥ `FISH_BIG_RADIUS`).
- **Места по порядку прихода**: зона помнит очередь `crew`, ушедшие вычёркиваются, вернувшиеся встают в конец. Опоздавший не выталкивает давно кормящегося.
- Кормящиеся помечаются `netting` в `publicState` — клиент рисует развёрнутую сеть.

### 🪙 Монеты — вторая валюта

Падают **только с пиратов**: `PIRATE_COINS = 1` за обычного, `PIRATE_BOSS_COINS = 2` за 👑-босса
(`pirateCoins(boss)` в `server/config.js`). Начисляются в `sinkShip` там же, где награда золотом.

- Живут **на игроке** (`player.coins`), а не в `stats`: это кошелёк, а не статистика матча —
  в лидерборд они не идут.
- В `publicState` прячутся **ровно как золото**: чужой кошелёк приходит как `null`.
- Партии, сохранённые до ввода валюты, поля не имеют — везде читаются через `|| 0`.
- **Тратить пока не на что.** Покупка за монеты — отдельная задача.

### 🎖 Перки — что покупается за монеты

Схема: **золото — цена, монета — разрешение**. Золота в партии много, монет единицы, поэтому
монета решает, сколько перков вообще можно позволить за бой, а не «накопи и купи всё».

Перк принадлежит **игроку** (`player.perks[ключ]`), а не кораблю: статы судов читаются через
`SHIP_TYPES[type]` почти в сотне мест, и апгрейд отдельного корпуса потребовал бы протаскивать
владельца во все. Перки же врезаются в считаные формулы.

| Ключ | Перк | Что меняет | Где врезано |
|---|---|---|---|
| `battery` | 🏰 Береговая батарея | ответка порта `PORT_RETURN_DMG` → `BATTERY_RETURN_DMG = 40` | `portReturnDmg` |
| `market` | 📈 Торговый ряд | доход порта × `MARKET_INCOME_MULT = 1.5` | `portIncome` |
| `drydock` | ⚓ Сухой док | свои суда у базы чинятся на `DRYDOCK_HEAL = 0.05` в радиусе `DRYDOCK_RADIUS = 240` | `applyBasePerks` |
| `lighthouse` | 🗼 Маяк | обзор вокруг базы +`LIGHTHOUSE_EXTRA = 260` | клиент, `visionCircles` (число едет в `perkFx`) |
| `garrison` | 🛡 Гарнизон | прочность аванпостов × `GARRISON_HP_MULT = 1.5`, включая уже стоящие | `outpostMaxHp` + докрутка при покупке |
| `warehouse` | 📦 Склад | +`WAREHOUSE_INCOME = 2` золота с каждого аванпоста | `applyOutpostPerks` |
| `bastion` | 🏯 Бастион | 🏰-форт стреляет дважды за тик, цель выбирается заново | `applyOutpostPerks` |
| `fishery` | 🐟 Рыбный промысел | улов баркасов × `FISHERY_MULT = 2` | `fishIncomeFor` |
| `portRepair` | 🔧 Ремонт порта | **расходник**: чинит порт на `PORT_REPAIR_FRAC = 0.5` от `PORT_HP` | `buyPerk`, применяется сразу |
| `grapnels` | 🪝 Абордажные крючья | лут с обломков → `GRAPNELS_LOOT_FRAC = 0.8` | `wreckLootFrac` в `sinkShip` |
| `lateen` | ⛵ Косой парус | встречный ветер не режет ход (`max(1, k)`) | `windMoveMultFor`, `windMult` в rt |
| `shipyard` | 🛠 Верфь на потоке | корабли дешевле на `SHIPYARD_DISCOUNT = 0.1` | `shipPrice` |

- **Расходники** (`instant: true`, сейчас это только 🔧 ремонт порта) в `player.perks` не пишутся:
  срабатывают в момент покупки и берутся сколько угодно раз. Постоянные перки — ровно по одному.
- В `publicState` перки прячутся **как золото**: чужие приходят как `null`.
- Клиенту уходят `perkShop` (ключ → цена), `perkFx` (числа, нужные для отрисовки) и
  `shipPrices` — уже со скидкой, чтобы витрина не считалась в уме.
- Партии, сохранённые до ввода перков, поля не имеют — везде читается через `?.` и `|| 0`.

⚠ **В ДУЭЛИ перков и монет нет вовсе** (`perksEnabled`): там нет ни дохода, ни аванпостов, ни
лута с судов — половина списка бессмысленна, а вторая ломает стартовый бюджет. Монеты за пиратов
там не начисляются, витрина не приходит, покупка отклоняется.

### 🏴‍☠️ Куш за разбитую базу (`tributeFor`)

Меряет **путь игрока за партию**, а не его казну (замер 12 партий: у проигравшего в казне ноль в 11 случаях):

```js
raw = goldCollected×0.18 + damageDealt×0.10 + shipsSunk×12 + gold×0.05
куш = clamp(raw, TRIBUTE_MIN = 100, TRIBUTE_MAX = 1000)
```

Ориентиры: ранний вылет ≈ 180, обычная партия ≈ 450, долгая и богатая ≈ 870–980.

### Мёртвые константы

`PORT_INCOME_TURN_FACTOR` (доход больше не срезается по числу ходов) и `PORT_DMG_TO_SHIPS` живут только в снапшот-тесте `test-config.mjs`.

## 9. Карта

Генерация детерминированная по seed (`mulberry32`), `server/mapgen.js`.
⚠ **Порядок вызовов `rnd()` менять нельзя** — ломает воспроизводимость карт и тесты.

- Размер `MAP_W = 1600` × `MAP_H = 1200`. Дуэль — своя маленькая карта без баз и островов (`mapScale = 0.7`).
- **Базы** по углам (`BASE_CORNER_MARGIN = 200`, `BASE_RADIUS = 105`, джиттер `BASE_JITTER = 30`). 2 игрока — по диагонали, 3–4 — по углам.
- **Лут-острова**: `игроков + LOOT_COUNT_EXTRA = 3` штук, в центральной зоне, по 100–300 золота.
- **Рыбные места**: `FISH_COUNT = 3` зоны радиусом 90–120. В режиме «Развитие» — плюс своя зона у каждой базы, и все зоны крупные.
- Острова в логике — круги; `shape` (полигон) только для отрисовки.

### 🐟 Миграция рыбных мест

Зоны очень медленно блуждают вокруг места рождения:

- шаг `FISH_DRIFT_PER_TURN = 2` px за смену хода, `FISH_DRIFT_RT = 0.35` px/с в реалтайме;
- якорь `FISH_HOME_RADIUS = 280` — дальше от дома не уходят;
- `FISH_MIN_GAP = 240` между целями зон, плюс отступ от баз и островов — в кучу не съедутся.

## 10. 🏴‍☠️ Пираты

Нейтральные NPC, `owner = -1`, статы в `PIRATE`: 80 HP, урон 12, дальность 130, ход 80.

- На карте **всегда** держится `PIRATE_MAX = 2`: растворившегося тут же заменяет новый в другом месте. Пополнение гарантированное, не рандомное — раньше игрок видел одного пирата всю половину партии.
- **Ходит раз в цикл**: у каждого пирата есть `turnSlot` — он двигается только после хода «своего» игрока. Иначе при 3–4 игроках успевал бы 3–4 раза за круг.
- **Босс**: шанс `PIRATE_BOSS_CHANCE = 0.14`, `PIRATE_BOSS_HP = 220`, куш 400–800.
- **Награда**: обычный 150–350 (`PIRATE_BOUNTY_MIN/RAND/STEP`), босс 400–800.
- **Поведение** (`pirateAct`): «вовлечён», если рядом корабль в пределах `max(move, fireRange) × PIRATE_ENGAGE_MULT = 1.2`. Дерётся, если добьёт одним залпом или переживёт ответку; босс агрессивен всегда и добивает подранков. Обычный пират **не гоняется** за флотом — иначе партия не сходится.
- **Залп пирата** (`pirateVolley`): разворачивается бортом к цели и бьёт всех игроков в секторе плоским `PIRATE.dmg`.
- **Исчезновение**: `PIRATE_DESPAWN_CHANCE = 0.08` за ход, но не раньше `PIRATE_MIN_LIFETIME = 5` ходов и никогда — последний пират на карте.
- Легаси-константы `PIRATE_REVENGE_SHOT`, `PIRATE_FLEE_CHANCE`, `PIRATE_CALM_CHANCE`, `PIRATE_SPAWN_CHANCE` больше не используются.

## 11. ⛺ Аванпосты

Залутал остров → можешь поставить аванпост и прокачивать его.

| Уровень | Иконка | Цена | HP | Доход | Перк |
|---|---|---|---|---|---|
| 1 | ⛺ | 150 | 120 | 3 | дозор (снимает туман вокруг острова) |
| 2 | 🏪 | 250 | 180 | 8 | + чинит свои корабли в радиусе (3% макс. HP) |
| 3 | 🏰 | 400 | 260 | 12 | + береговая пушка, 15 урона по ближайшему врагу |

- `OUTPOST_RADIUS = 240` — радиус всех перков. `OUTPOST_BUILD_REACH = 70` — как близко должен стоять корабль-строитель.
- **Первая постройка** требует своего корабля у берега (он привозит гарнизон). **Апгрейд** — кликом по самому аванпосту, корабль не нужен; апгрейд заодно отстраивает до полной прочности.

- В мирное время форт не стреляет.

## 12. 🌬 Ветер

Работает **во всех режимах**. Дальность и скорость зависят от курса:

```js
множитель = 1 + WIND_STRENGTH × сила × cos(курс − направление ветра)
```

`WIND_STRENGTH = 0.35` — до ±35% дальности. Контур хода получается каплевидным.

- **Пошагово**: ветер живёт в `game.wind`, меняется между ходами (`driftWind` в `advanceTurn`) — в свой ход он стабилен, планировать можно. Доворот `WIND_TURN_STEP = 0.3` рад/ход, сила `WIND_STR_STEP = 0.1`; новая цель раз в круг.
- **Реалтайм**: тот же `game.wind` крутит `tickWind`, новая цель раз в `RT.WIND_MS = 35000`, доворот `RT.WIND_TURN` рад/с.
- Отказ «не дотянул из-за ветра» — отдельный ключ `err.windTooFar`, чтобы игрок понял причину.

## 13. 🌫 Туман войны

⚠ **Туман реализован ЦЕЛИКОМ НА КЛИЕНТЕ** (`public/js/game.js`, секция `fogActive`/`visionCircles`/`drawFogOverlay`). Сервер по-прежнему шлёт каждому полный стейт — продвинутый игрок видит всё через DevTools. Это осознанный долг, расписанный в `TODO.md`.

Что уже честно: **журнал** абстрагирован (`logEvent` шлёт под туманом обобщённую запись без деталей), так что текстовой утечки нет.

Правила видимости на клиенте:

- своя база + `FOG_BASE_EXTRA = 200`;
- каждый свой корабль: `max(move, fireRange) × FOG_SHIP_MULT = 1.3`;
- свои аванпосты: радиус перков;
- только что потопленные свои корабли дают затухающий круг — туман закрывается плавно.

Разведанное запоминается сеткой `FOG_CELL = 48` (не чаще ~7 раз/с — иначе GC-дрожь), HP чужих баз запоминается «последним виденным». Память сбрасывается при смене партии.

Туман выключается настройкой партии (`config.fog`), не работает в хотсите, снимается читом `nofog` и перебивается отладочной кнопкой в обе стороны.

`GAME_MODES` в `server/config.js`. На статы кораблей режимы **не влияют** — только стартовые условия и правила.

| Ключ | Что меняет |
|---|---|
| `classic` | Поведение по умолчанию |
| `deathmatch` | `startGold: 3500`, боты агрессивнее |
| `develop` | Мирные `peaceRounds: 10`, запретка у чужих баз `peaceBaseKeepout: 427`, своя рыбозона у каждой базы, все зоны крупные |

**Мирное время** (`isPeace`): нельзя атаковать игроков, их базы и постройки, нельзя подходить к чужой базе ближе `peaceBaseKeepout`. Пиратов бить можно. Пошагово меряется раундами, в реалтайме — временем (`RT.PEACE_MS_PER_ROUND = 20000`, то есть 10 раундов ≈ 3,3 минуты).

- `config.listed` — онлайн-партия: попадает в браузер лобби и в лидерборд.

## 15. ⚡ Реалтайм («Полный вперёд», бета)

Движок — `server/rt.js`, один `setInterval` на партию, шаг `RT.TICK_MS = 100`. Всё состояние в `game.rt` (обычный объект — переживает сохранение в БД).

**Порядок тика:**

```
tickWind → tickMovement → tickEconomy → tickOutposts → driftFishZones → tickPirates → tickBots
→ рассылка (RT.BROADCAST_MS = 250) → сохранение (RT.SAVE_MS = 5000)
```

- `dt` ограничен 500 мс — после лага или деплоя мир не телепортируется на минуты вперёд.
- Тик асинхронный (рассылка ждёт сокеты) и защищён флагом `busy` — второй поверх первого не идёт.

**Движение**: приказ «плыть» ставит `ship.dest`, дальше корабль идёт сам. Курс доворачивает с ограниченной скоростью (`RT.TURN_RATE` по классам: линкор 0.65 рад/с, баркас 1.7), корабль всегда идёт по курсу — получается дуга разворота. Круче 90° — ещё и `RT.TURN_SLOW = 0.35` к скорости. Это закрывает эксплойт «отстрелялся бортом → мгновенно развернулся другим»: перекладка линкора стоит ~5 секунд. Скорость = `move / RT.MOVE_SECONDS` (15 с на свой `move`), умноженная на ветер. Прямо по курсу суша → доворот на ближайший свободный угол.

**Бой по кулдаунам**: `RT.CD_BROADSIDE_MS = 8000` (у каждого борта свой), `RT.CD_MORTAR_MS = 14000`, `RT.CD_REPAIR_MS = 8000`. Метки лежат на корабле в `ship.cd` и сериализуются клиенту — он сам рисует отсчёт.

**Экономика по таймерам**: `RT.INCOME_MS = 10000` (доход порта), `RT.FISH_MS = 10000` (рыбалка), `RT_OUTPOST_MS = 10000` (аванпосты).

**⏸ Пауза**: ставит и снимает **любой** живой участник (анти-грифинг: вечной паузой не запереть). На паузе тик спит. При снятии `rtShift` сдвигает **все** абсолютные часы партии на длительность паузы — кулдауны, доходы, мирное время, агро ботов, пиратов. Не трогает `nextCast`/`nextSave`: это wall-clock темп рассылки, а не игровое время.

**Боты в реалтайме** — отдельный простой мозг `botThink` (раз в `RT.BOT_THINK_MS = 1300`, верфь не чаще `RT.BOT_BUY_MS = 12000`), но все его действия идут через тот же `applyAction`.

## 16. 🤖 Боты

Три уровня, имена — ключи словаря (`BOT_NAMES` в `server/bot.js`, тексты в `bot.*`):

| Уровень | Кто | Как думает |
|---|---|---|
| `easy` | Юнга | Видит **случайную горстку** из `BOT_EASY_SAMPLE = 6` вариантов и берёт лучшее из неё, оценки зашумлены. Размер горстки — и есть ручка сложности. |
| `mid` | Боцман | Полная эвристика + урезанный просмотр (`BOT_PLAN_K_MID = 3`). |
| `hard` | Адмирал | Полная эвристика + просмотр `BOT_PLAN_K = 5` кандидатов, фокус раненых, удушение экономики, ранняя агрессия. |

**Как принимается решение** (`chooseBotAction`):

1. `buildCandidates` порождает все осмысленные действия с эвристическими оценками.
2. Кандидаты сортируются; топ-`k` прогоняются на **копии партии** (`structuredClone`) и ранжируются не по приоритету, а по `boardValue` получившейся позиции.
3. Если после действия ход ещё наш — доигрывается лучшее продолжение со скидкой `BOT_PLAN_DISCOUNT = 0.7`.

⚠ **Почему именно так**: первая версия планировщика складывала эвристические *оценки* («сделай это, потом лучшее из оставшегося») и дала −4 победы против +30 без планировщика. Приоритеты — не ценность: «не стрелять» сохраняет лучший выстрел на потом, и сумма приоритетов такое поощряет. Сравнивать надо позицию, а не приоритеты.

**`boardValue`** (оценка позиции с моей стороны) складывает: живучесть и огневую мощь флота (`hp + dmg×2`), HP портов (чужой дорожает по ходу партии), казну (`BOT_GOLD_W = 0.7` — реальный курс золота в ценность), непокрытую угрозу у своего порога (`BOT_HOME_THREAT_W = 2.5`), пиратов как угрозу **и** как приближающиеся деньги, аванпосты как поток дохода, готовность борта (`BOT_BROAD_READY_W = 1`), и «потенциал» — близость к кладам и рыбе, затухающий по ходу партии.

**Все веса — переменные среды** (`BOT_FOCUS_W`, `BOT_CONVOY_W`, `BOT_PLAN_K`, `BOT_PORT_W`, `BOT_DEFENCE_W`, …), чтобы подбирать их прогоном `ab-bot.mjs`, а не на глаз. Замеры записаны прямо в комментариях рядом с константами.

**Расписание ходов** (`server/index.js`): первый ход бота в свой ход — пауза `BOT_DELAY_MS = 1500` «на раздумье», последующие суда того же хода — `BOT_FOLLOWUP_MS = 650`. Невалидный ход бота страхуется `skip`.

**Все люди сдались** → `maybeAutoFinish` доигрывает за ботов синхронно и завершает партию, чтобы никто не смотрел, как боты воюют друг с другом.

| `botlog` | 🐞 Поток решений бота |

**Рассылка персональная**: `broadcastState` обходит сокеты комнаты и шлёт каждому свой `publicState(game, pid)` — чужое золото скрыто, приватные записи журнала отфильтрованы.

### 🔗 Превью ссылок (Open Graph)

Ссылку на партию кидают в мессенджер — тот идёт за ней своим ботом и рисует карточку. Логика — `server/og.js`, подстановка — `ogBlock`/`renderPage` в `server/index.js`.

Про бота мессенджера важно знать три вещи: **он не выполняет JS**, **у него нет кук** и **он ходит один раз, запоминая карточку надолго**. Из них следуют все решения ниже.

**⚠ В описание идёт только НЕИЗМЕНЯЕМОЕ.** Карточка кэшируется у мессенджера намертво, поэтому «2 из 4 капитанов» повисло бы в чате навсегда и устарело через минуту. Берём то, что задано при создании и больше не меняется: режим, число мест, таймер, туман, реалтайм (`gameFacts`). Ни счёта, ни очереди хода, ни победителя. Тест `test-og.mjs` прогоняет партию от лобби до финала и требует, чтобы приметы не дрогнули.

**⚠ Никаких ников.** Превью видит любой, кому попала ссылка, включая ботов-пересыльщиков и превью-прокси. Кто играет — не их дело; отдельная проверка в тесте.

**Язык превью — отправителя.** Сервер не знает, кто кинул ссылку (бот приходит анонимно), поэтому язык кладётся В САМУ ССЫЛКУ на клиенте: `shareUrl()` в `public/js/game.js` добавляет `?l=<язык>` при копировании. Нет параметра — берём язык создателя партии (`hostPid` → профиль), нет и его — дефолт (`previewLang`). ⚠ На саму страницу параметр не влияет: живой человек получает её по обычному правилу профиль → кука → дефолт.

**Куда вставляются теги.** В начало `<head>`, но **после `<meta charset>`**: дальше в голове лежит вшитый словарь на десятки килобайт, а краулер читает только начало страницы. Готовая страница в памяти при этом не меняется — теги подклеиваются к копии перед самой отправкой (см. раздел 20 про кэш страниц).

**Ссылка на несуществующую партию** отдаёт общую карточку главной — протухшее приглашение выглядит как приглашение в игру, а не как ошибка.

Картинка — `public/og-card.png`, 1200×630, абсолютным адресом (из `BASE_URL`, иначе из заголовков запроса). Одна на всё: текст мессенджер рисует сам из `og:title`/`og:description`, поэтому вписывать его в пиксели нельзя — пришлось бы держать по картинке на язык.

**Строка ввода — это и чат, и консоль читов.** Сервер сперва сверяет текст со списком в `server/cheats.js`; распознанный код **никогда** не уходит в чат, даже когда читы выключены — иначе коды палились бы.

## 18. Личность, аккаунты, сессии

Две роли (`server/auth.js`):

- **Аккаунт** (Google): `pid = googlePid(sub)` — стабилен на любом устройстве. Серверная сессия в httpOnly-cookie `sb_session`, TTL 30 дней, хранилище в памяти + таблица `sessions` (грузится на старте).
- **Гость**: случайный токен в localStorage, `pid = pidOf(token)`. Хватает для игры с ботом и хотсита.

- Онлайн-партии требуют аккаунт, когда Google-вход настроен.
- Ник аккаунта при входе: **сохранённый** > явно введённый > имя из Google > префикс почты. Сохранённый главнее, чтобы вернувшийся получил свой ник, а не тот, что остался в localStorage от чужого аккаунта на этом устройстве.
- Хотсит: игроки — это `pid#0`, `pid#1`, …, а `hotseatOwner` ходит за того, чья очередь.

## 19. База данных

Два движка за одним интерфейсом (`server/db.js`): **SQLite** локально (`node:sqlite`, без зависимостей), **MySQL** на проде при заданном `DATABASE_URL`/`DB_*`.

| Таблица | Поля |
|---|---|
| `players` | `token` (pid), `nick`, `email`, `provider`, `avatar`, `lang`, `created_at` |
| `games` | `id`, `status`, `state` (весь JSON партии), `created_at`, `updated_at` |
| `results` | `game_id`, `player_token`, `placement`, `win`, `damage`, `sunk`, `lost`, `gold`, `finished_at` |
| `sessions` | `token`, `pid`, `created_at` |

- Миграции — мягкие: новые колонки добавляются `ALTER TABLE` в try/catch.
- Партия сохраняется целиком после каждого действия (`persistAndBroadcast`); в реалтайме — не чаще `RT.SAVE_MS`.
- `updatedAt` — отметка активности, по ней сборщик чистит заброшенное.

## 20. Локализация — правила, которые держат всё

Подробности (как добавить строку, как устроены словари, какие тесты стерегут) — в `README.md`, раздел «Языки интерфейса». Здесь — только инварианты, которые нельзя нарушать в игровом коде:

1. **Сервер не шлёт готовых фраз.** В одной партии игроки с разными языками, а процесс один. Наружу уходят только ключи и числа: отказы `{ error: 'err.x', params }`, журнал `{ k: 'log.x', p: {...} }`, типы кораблей/режимов/построек. Фразу собирает клиент (`tr` в `public/js/i18n.js`).
2. **Текст в страницы подставляет сервер, а не браузер** (`buildPage` в `server/index.js`). Иначе на медленном канале человек несколько секунд видит чужой язык.
3. **Язык = профиль → кука `sb_lang` → дефолт** (`pickLang`). `Accept-Language` не смотрим сознательно: в инкогнито браузер шлёт `ru-RU`, и украинский дефолт ломался ровно для тех, ради кого он сделан.
4. **Формулировки журнала — в именительном падеже**: «🧭 {{nick}} — ход: {{ship}}», а не «ведёт {{ship}}». Иначе во всех трёх языках ломаются склонения.
5. ⚠ **Переменная с именем `t` в клиентском коде затеняет переводчик.** В `public/js/game.js` из-за этого пришлось переименовать `t` → `type` в отрисовке верфи.

## 21. Журнал и события

Два разных потока, их легко перепутать:

| | `game.log` | `game.events` |
|---|---|---|
| Что | История партии текстом | Что показать анимацией |
| Формат | `{ t, type, k, p, to? }` | `{ type: 'shot'\|'move'\|'explosion'\|'gold'\|'repair'\|'volley', ... }` |
| Живёт | последние 80 записей, в БД | до следующего хода |
| Кому | всем, кроме записей с `to` | всем |

- **`pushLog`** пишет запись, **`L('move', {...})`** — сахар для `{ k: 'log.move', p }`.
- **`logEvent(detailed, abstract)`** — под туманом пишется абстрактная версия без деталей (что/где/сколько), иначе подробная.
- **Приватные записи**: поле `to` = pid адресата. `publicState` фильтрует: `log.filter(l => !l.to || l.to === viewerPid)`. Так сделана сводка доходов — соперник не видит твою экономику.
- **Сводка доходов**: `earn(game, player, amount, kind)` копит по статьям (`port`, `support`, `fishing`, `loot`, `outpost`, `bounty`, `wreck`, `tribute`, `cheat`), `flushEarnings` в конце хода отдаёт одной строкой «рыбалка +35, аванпосты +20». Типы статей — ключи `income.*`.
- **`eventSeq`** растёт при каждой новой серии событий: клиент проигрывает анимации только при смене этого номера.
- **Записи со старым полем `text`** (сохранённые партии, отладка, читы) клиент показывает как есть.

**Звук** (`public/js/audio.js`) реагирует на события боя и на **ключи** записей журнала (`LOG_SOUNDS` по `entry.k`). ⚠ Раньше он матчил эмодзи в тексте записи — при переходе на ключи это молча роняло весь обработчик состояния (а с ним автопропуск и туториал). Обработчик теперь обёрнут в try/catch, но правило простое: **звук ключами, не текстом**.

## 22. Статистика и лидерборд

`player.stats`: `damageDealt`, `shipsSunk`, `shipsLost`, `goldCollected`, `shotsFired` + «нпс-доли» `npcDamage`, `npcSunk`, `npcGold`.

**В лидерборд идёт бой только против живых людей.** Из полных статов вычитается доля, набитая на NPC (пираты `owner = -1` и игроки-боты) — см. `resultRows` в `server/db.js`. Полные статы остаются для рекапа матча и сим-баланса.

**Ranked** (`isRanked`) = онлайн-партия (`config.listed`) и **не** реалтайм (он в бете). Игры с ботами и хотсит не засчитываются — нельзя нафармить статистику.

Очки: `победа × 3 + второе место × 1`, сортировка по очкам → победам → урону, топ-50.

## 23. 🐞 Отладка и читы

**Режим отладки** — `npm run debug` (то же, что `SB_DEBUG=1 npm run dev`). Добавляет:

- поток решений бота под картой (что выбрал, из чего выбирал, сколько золота, как оценивает позицию);
- финансы всех игроков в стейте (видно казну бота);
- панель над картой: переключить туман в обе стороны, перенести/вылечить любой корабль, подсадить пирата или любой корабль любому игроку, +500 золота, «👁 глазами бота», «⏭ пропускать ходы».

В проде выключен, наружу уходит только флаг. Отладочная панель и поток решений бота **не переводятся намеренно** — это внутренний инструмент.

**Читы** (`CHEATS_ENABLED`, по умолчанию выключены): `motherlode` (+1000 золота), `geraldford` (чит-авианосец, не больше одного на игрока), `nofog` (переключить туман). Коды живут **только** в `server/cheats.js` и в клиент не попадают.

## 25. Инварианты — то, что нельзя ломать

1. **Вся валидация на сервере.** Клиент рисует и предлагает; правила знает только `applyAction`. Боты ходят через неё же — лазейки у ИИ и человека одинаковые.
2. **Сервер не шлёт готовых фраз** — только ключи и числа (раздел 20).
3. **Порядок вызовов `rnd()` в `mapgen.js` менять нельзя** — ломает детерминизм карт.
4. **Все числа баланса — в `config.js`.** Веса эвристик бота — в `bot.js`: это поведение, а не баланс.
5. **Реалтайм переиспользует кирпичи `game.js`** (потопление, пираты, рыбные слоты, `applyAction`), чтобы урон и награды не разъезжались с пошаговой игрой.
6. **`game` сериализуется целиком.** Ничего живого (таймеры, сокеты, функции) в него класть нельзя — иначе сохранение сломается.
7. **Записи журнала — в именительном падеже** (раздел 20).
8. **Звук — по ключам записей, не по тексту** (раздел 21).
9. **Читы живут только на сервере.**
10. **Лидерборд считает только бой против людей** (раздел 22).
11. **В превью ссылки — только неизменяемое и никаких ников** (раздел 17).
