# ⚓ Морской бой на листке в клетку

Тот самый улучшенный морской бой с задней парты: листок в клетку, линейка, карандаш —
острова, флот и добыча. Теперь в браузере и по интернету.

📖 **Правишь код?** Все механики, формулы и инварианты по блокам — в [MECHANICS.md](MECHANICS.md):
что за правило, где живёт, какой константой крутится. Осознанные долги — в [TODO.md](TODO.md),
прод и база — в [DEPLOY.md](DEPLOY.md).

## Запуск

```bash
npm install
npm run dev            # http://localhost:3456, авто-перезапуск при правках
npm run debug          
```

### Версии сборки

Номер версии живёт в `package.json` и показывается в подвале главной: `v1.3.0`. Номер сборки
(количество коммитов) и дата последнего изменения прячутся в подсказке при наведении, уходят
в `/api/config` и печатаются в логе сервера при старте.

Стартовая `1.3.0` поставлена по трём волнам разработки: ядро игры (июнь), экономика и
реалтайм (июль), боты (сентябрь).

Поднимать версию вручную не нужно, есть три команды. Каждая двигает номер, делает коммит,
ставит git-тег и пушит всё вместе с тегом:

```bash
npm run release:patch   # 1.0.0 → 1.0.1   починили, поведение не менялось
npm run release:minor   # 1.0.0 → 1.1.0   добавили возможность
npm run release:major   # 1.0.0 → 2.0.0   сломали совместимость (сейвы, API, правила)
```

Обычные пуши версию не трогают — она меняется только этими командами, то есть ровно тогда,
когда ты решил, что это релиз. Если `.git` рядом нет (деплой распакованным архивом), подвал
покажет просто номер версии без хеша.

### 🐞 Режим отладки

`npm run debug` (то же самое, что `SB_DEBUG=1 npm run dev`) добавляет в игру:

- **консоль под картой** — поток решений бота: что выбрал, из чего выбирал, сколько у него
  золота и как он оценивает позицию. Тянется за верхнюю границу;
- **финансы всех игроков** в списке капитанов — видно казну бота;
- **панель инструментов над картой**: переключить туман (в обе стороны, даже в партии, где он
  выключен), перенести любой корабль, вылечить, подсадить пирата или любой корабль любому
  игроку, +500 золота, «👁 глазами бота» — его круги обзора, тревога у базы и выбранная цель,
  и «⏭ пропускать ходы» — свой ход сдаётся сам, партию доигрывают боты (удобно смотреть, как
  они играют, не кликая «Пропустить» каждый ход).

Без флага ничего этого нет и наружу не уходит — в проде режим выключен.

Локально ничего настраивать не надо: без переменных среды данные пишутся во встроенный
**SQLite** (файл `sea-battle.db` создаётся сам, без зависимостей и нативной сборки).

На проде (Render и т.п. с эфемерной ФС) задаётся **MySQL** через переменную
`DATABASE_URL` (или `DB_HOST/DB_USER/...`) — тогда движок сам переключается на неё, и данные
переживают деплой. См. `DEPLOY.md`. Хочешь локально проверить на MySQL — `npm run db:up`
(MySQL в Docker на 3307) и впиши `DATABASE_URL` в `.env` (`npm run db:down` — убрать контейнер).
Порт сервера меняется переменной `PORT`.

## Как играть

1. На главной вписываешь ник, выбираешь число игроков (2–4) и таймер на ход
   (без таймера / 1 / 2 / 5 минут) → «Создать баттл».
   Можно и наоборот — кнопка **«👥 найти игру»** на главной открывает список
   открытых лобби (обновляется в реальном времени); жми «Войти» и попадёшь в чужой баттл.
2. Получаешь ссылку вида `/game/XXXXXXX` — кидаешь друзьям. Они открывают её,
   вписывают ник и попадают в лобби.
3. Когда собрались (минимум 2), создатель жмёт «Начать баттл» — генерируется карта:
   базы-острова по краям, лут-острова и рыбные места в центре.
4. Ходят по очереди. За ход — **одно** действие:
   - **Купить** корабли на верфи (появляются у твоего порта);
   - **Собрать добычу**: любой корабль лутает остров с кладом, если дотягивается
     (рыбалка отдельного действия не требует — см. ниже);
   - **Передвинуть один корабль** «по линейке» — клик по кораблю → Плыть → точка
     в круге дальности;
   - **Выстрелить**: клик по кораблю → Стрелять → вражеский корабль или порт
     в круге дальности стрельбы.
5. Потопил корабль — лутаешь золото с обломков. Разбил порт — соперник выбывает,
   а ты забираешь **куш** — от 100 до 1000 золота, тем больше, чем крупнее партию он отыграл:
   сколько успел заработать, навоевать и потопить. Последний живой порт побеждает. 👑
   Порт очень прочный (840 HP), приносит немного золота каждый ход и **огрызается** 🏰
   по атакующему его кораблю (−25 HP, линкору −30: обломки достаются защитнику) — лёгким кораблём
   в одиночку базу не взять, да и линкору нужно несколько залпов — эффективнее
   давить несколькими кораблями.
   - **🐟 Рыбалка пассивная**: баркас, стоящий в рыбном месте, сам приносит золото
     (+5) в начале каждого твоего хода — действие на это не тратится. Место кормит
     не больше 4 судов (крупное — 5), очередь по приходу.
6. По морю бродят нейтральные **пираты** 🏴‍☠️: медленно дрейфуют между ходами,
   могут исчезать в тумане и появляться вновь. Потопи — забери награду (150–350 золота).
   Изредка приходит жирный **👑-босс** (220 HP) с большим кушем — 400–800 золота.
7. Соперник пропал? **«📯 Поторопить»** — ему уйдёт письмо (если входил через Google)
   и останется 10 минут на ход, иначе автопропуск. Сам безнадёжно застрял —
   жми **«🏳️ Сдаться»**; из лобби можно просто выйти.

Игра живёт по ссылке: можно закрыть вкладку и вернуться позже — состояние хранится
в MySQL и переживает рестарт сервера и деплой.

## Флот

| Корабль          | Цена | HP  | Урон | Дальность огня | Ход | Особое |
|------------------|------|-----|------|----------------|-----|--------|
| Рыбацкий баркас  | 60   | 30  | 5    | 70             | 180 | 🐟 +5 золота каждый ход в рыбном месте (пассивно) |
| Шхуна            | 110  | 60  | 15   | 110            | 170 | стартовый корабль ×2 |
| Бриг             | 220  | 110 | 28   | 140            | 135 | |
| Ремонтник        | 280  | 130 | —    | 115            | 135 | 🛟 чинит союзника (+15% его HP), 8 зарядов, сам не стреляет |
| Фрегат           | 380  | 170 | 42   | 165            | 110 | стартовый «крейсер»; 💥 залп + 🎯 мортира |
| Линкор           | 500  | 280 | 65   | 190            | 90  | 🏰 мортира по порту ×1.5 (≈98); 💥 залп + 🎯 мортира |

**💥 Бортовой залп** — основная атака боевых судов (шхуна и выше). Целишься в сторону —
стреляет весь борт с этой стороны, и достаётся **всем** вражеским кораблям в секторе
(≈46° в каждую сторону), включая пиратов и баркасы. Урон тем выше, чем ближе цель и чем
точнее она на траверзе: на краю сектора или радиуса остаётся 60%. По вражескому порту залп
бьёт символически — осада это дело мортиры. Каждый борт стреляет раз в ход и тратит манёвр.

**🎯 Мортира** — прицельный одиночный выстрел, только у фрегата и линкора. По судам бьёт
вполовину, зато по портам и аванпостам — в полную силу, и разрушить чужой аванпост можно
**только** ею.

Расстояния в игровых единицах, 1 клетка = 40. Стартовый капитал — 350 золота,
HP порта — 840.

## Игра по интернету

Сервер один на всех, ссылка ведёт на конкретную сессию. Чтобы друзья зашли извне:
- проще всего — туннель: `npx localtunnel --port 3456` или `cloudflared tunnel --url http://localhost:3456`;
- или задеплоить на любой VPS/хостинг с Node.js (нужен один процесс, БД — файл рядом).

## Необязательные настройки (переменные окружения)

| Переменная | Что включает |
|---|---|
| `GOOGLE_CLIENT_ID` | Кнопку «Войти через Google» (ник остаётся свой, почта — для уведомлений) |
| `SMTP_HOST`, `SMTP_PORT`, `SMTP_USER`, `SMTP_PASS`, `SMTP_FROM` | Письма «твой ход, 10 минут» при нажатии «Поторопить» |
| `BASE_URL` | Адрес сайта для ссылок в письмах (например `https://game.example.ua`) |
| `PORT` | Порт сервера (по умолчанию 3456) |

Без этих переменных всё работает: вход остаётся гостевым (ник + токен в браузере),
а «Поторопить» просто включает 10-минутный таймер без письма.

## Языки интерфейса

Украинский (по умолчанию), русский и английский. Словари — `public/locales/{uk,ru,en}.json`, движок —
[i18next](https://www.i18next.com/) (UMD-сборка лежит в `public/vendor/`, сборки в проекте нет —
обновить файл из npm: `npm run vendor:i18next`).

**Откуда берётся язык** (см. `pickLang` в `server/i18n.js`): профиль аккаунта → кука
`sb_lang` → дефолт. Вошёл через Google — язык едет за тобой на любое устройство (колонка
`lang` в `players`); гостю хватает куки.

⚠ `Accept-Language` не смотрим **сознательно**. С ним «вежливое уважение к языку браузера»
ломало главное правило: в инкогнито куки нет, браузер шлёт `ru-RU` — и человек вместо
украинского получал русский. В Украине русская локаль браузера обычное дело, так что заголовок
уводил на русский как раз тех, ради кого украинский и сделан дефолтом. Правило простое:
**не выбирал язык — видишь дефолтный**; выбрал переключателем — запомнится в куке и профиле.

**Текст подставляет СЕРВЕР, а не браузер.** Страницы отдаются не статикой, а рендером
(`buildPage` в `server/index.js`): он проходит по `data-i18n` и кладёт в HTML готовые строки
нужного языка, правит `<html lang>` и вшивает словарь в `<head>`. В браузер уходят байты уже
на нужном языке — для первой отрисовки JS не нужен вовсе.

Так было не сразу: сначала перевод подставлял клиент после разбора страницы. На локалхосте это
незаметно (скрипты грузятся мгновенно), но на медленном канале HTML успевает отрисоваться раньше,
чем догрузятся i18next и `i18n.js`, — и человек несколько секунд смотрит на чужой язык.
Правило простое: **язык страницы решается до отправки, а не после**.

Готовые страницы лежат в памяти по паре (файл, язык) — их шесть, пересобираются по mtime, так
что `--watch` и правки словарей подхватываются сразу. Разметка в `public/*.html` — шаблон на
исходном русском; какой язык там лежит, пользователю не видно.

На клиенте `i18n.js` остаётся для динамики: текст, который рисует JS (журнал, тосты, панели),
переключатель языка и перерисовка по `data-i18n`, когда язык меняют на лету.

**Правило, на котором всё держится:** в одной партии игроки с разными языками, а сервер
один — значит сервер не шлёт готовых фраз, только ключи и числа, а текст рисует клиент.
События боя (`pushEvent`) структурные с самого начала, поэтому журнал переводится даром.

**Что переведено:** всё, что видит игрок — главная, правила, игровой экран, инфобаза (вики),
туториал, **журнал боя**, **тексты отказов**, имена кораблей, режимов и построек. Дебаг-панель
и поток решений бота (`SB_DEBUG=1`) не переводим намеренно: это внутренний инструмент.

**Как сервер «говорит ключами».** Готовых фраз он не шлёт вообще:

| что | как выглядит на проводе | где текст |
|---|---|---|
| отказ | `{ ok:false, error:'err.notYourTurn' }` (+ `params`) | `err.*` в словаре |
| журнал | `{ k:'log.move', p:{ nick, ship:'ship.brig.name' } }` | `log.*` |
| корабль/режим/постройка | только тип: `brig`, `duel`, уровень `1` | `ship.*`, `mode.*`, `outpost.*` |
| метки лобби | `[{ k:'tag.timer', p:{ min:2 } }]` | `tag.*` |

Собирает фразу клиент — `tr(key, params)` в `public/js/i18n.js`. Параметр, который сам похож
на ключ (`ship.brig.name`), она тоже переводит, а массив ключей склеивает через запятую — так
в журнал попадает список купленных судов. Запись со старым полем `text` (сохранённая партия,
дебаг, чит) показывается как есть.

⚠ Формулировки в журнале построены так, чтобы подставляемое слово стояло в именительном падеже
(«🧭 {{nick}} — ход: {{ship}}», а не «ведёт {{ship}}»). Иначе во всех трёх языках ломаются
склонения. Держись этого стиля, когда добавляешь записи.

**Склонения.** Числительные идут через `count`: `t('game.peaceRounds', { count: 3 })` → «3 раунда»
(в ru/uk три формы, в en две). Формы лежат как `ключ_one`, `ключ_few`, `ключ_many` — набор форм
для каждого языка проверяет тест через `Intl.PluralRules`.

**Как добавить строку:** кладёшь ключ в `ru.json` (эталон) и в оба перевода, в разметке
пишешь `data-i18n="ключ"` (или `data-i18n-html` для строк с тегами, `data-i18n-attr="title:ключ"`
для атрибутов), в коде — `t('ключ')`. `node test-i18n.mjs` проверит, что ключ есть везде,
что наборы ключей в словарях совпадают, что формы склонений полные и что плейсхолдеры
`{{...}}` не разъехались. Ключи ищутся и в тернарниках (`t(a ? 'x' : 'y')`) — опечатку поймает.

Тест сканирует и сервер: ключи из `error: 'err.…'`, `L('…')` и `{ k: 'log.…' }` обязаны быть
в словарях, а на каждый класс из `SHIP_TYPES`, режим из `GAME_MODES`, уровень `OUTPOST_LEVELS`
и бота из `BOT_NAMES` обязан найтись перевод — иначе игрок увидит голый ключ. Он же следит,
чтобы в конфиг не вернули человекочитаемые имена, и сверяет **алфавиты**: в украинском словаре
не должно быть ы/ъ/ё/э, в русском — і/ї/є/ґ, в английском — кириллицы вообще. Это ловит самую
частую порчу: забыли перевести строку и оставили её из соседнего языка.

⚠ Осторожно с переменной с именем `t` в клиентском коде: она затенит переводчик. В `game.js`
из-за этого пришлось переименовать `t` → `type` в отрисовке верфи.

**Как добавить язык:** код в `LANGS` (`server/i18n.js`), название в `NAMES`
(`public/js/i18n.js`), файл `public/locales/<код>.json`.

**Имена ботов** тоже ключи (`bot.hard.0` → «Адмірал Ґрей» / «Адмирал Грей» / «Admiral Grey»):
звание переводится, и каждый видит его на своём языке. Ник живого игрока — как он его ввёл;
`tr()` пропускает всё, что на ключ не похоже.

## Технологии

- **Сервер**: Node.js + Express + Socket.IO (вся логика и валидация ходов на сервере).
- **БД**: два движка за единым интерфейсом (`server/db.js`) — локально встроенный
  **SQLite** (`node:sqlite`, без зависимостей), на проде **MySQL** (`mysql2`) при заданном
  `DATABASE_URL`/`DB_*`. Хранит игроков, сессии игр, результаты, лидерборд. См. DEPLOY.md.
- **Клиент**: ванильный JS + Canvas, без сборки. Личность игрока — ник + токен
  в localStorage (без регистрации).
- **Локализация**: i18next (вендорится в `public/vendor/`, словари — `public/locales/`).
